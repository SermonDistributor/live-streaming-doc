# Amazon IVS, AWS media pipelines and existing hosted URLs

## IVS low-latency channels

Identify the AWS region, church-owned account and channel ARN. Use server-side AWS SDK authentication/SigV4 and a scoped IAM role or credentials; never ask for root credentials. GetChannel confirms account, region, ARN, playback URL, authorization setting and recording configuration. GetStream reports active status; distinguish ChannelNotBroadcasting from wrong account, access denied or unavailable. Display the existing channel's label to the editor. Channel provisioning and key retrieval are separate explicit operations. A church can adopt a playback URL without exposing its stream key to Joomla.

| Capability | Integration contract |
| --- | --- |
| On-site player | Use the playback URL returned by GetChannel. Prefer Amazon IVS Web Player for low-latency playback. Use a supported alternative only with tested limits, including Safari. Respect playback authorization and issue tokens after Joomla ACL checks where the channel requires them. |
| Remote scheduling | A Low-Latency channel remains available between broadcasts. Joomla owns the service calendar. Do not start a paid MediaLive channel or issue StopStream when a countdown expires. |
| Status | Consume verified AWS EventBridge IVS stream-state events routed by a church-configured target/bridge, or poll GetStream. Local HTTPS callback is not automatically registered with AWS. Acknowledge transport according to the selected AWS target, restrict source account/region/channel, and authenticate the relay. |
| Identity | Channel ARN persists; stream ID is per broadcast. Keep channel, stream ID, recording configuration and S3 prefix distinct. ListStreamSessions assists reconciliation. Check the underlying stream even if a notification is missing or late. |
| Recording | Church enables auto-record-to-S3 and grants the integration access to the specific bucket/prefix. Wait for the recording-end event/metadata or handle failure. Media exists as HLS manifests, segments, thumbnails and metadata rather than an automatic MP4 file. |
| Local replay | Get the specific completed prefix. Adopt a validated complete HLS tree or package a compatible local audio/video file on an authorized worker. Preserve relative URIs and segment boundaries. Stage outside public paths. Access to IVS alone does not grant S3 or KMS decryption rights. |
| Costs and control | Input time, viewer output and retention/storage have different owners. Show the church the upstream account/resource, region and archive settings; never auto-enable high-cost renditions, public buckets or global distribution. |

Suggested permissions are operation-specific: ivs:GetChannel, ivs:GetStream and ivs:ListStreamSessions for observation, ivs:ListChannels only for discovery. Stream keys, provisioning, EventBridge rules and changing recording configuration are higher-privilege actions. Restrict S3 listing and reading to the recording location and kms:Decrypt to the relevant key only when required. Token signing material stays server-side. Treat multi-region account adoption as separate validated profiles.

Test each side independently: active stream without S3 permission still plays; completed S3 recording with IVS offline still archives; duplicate EventBridge notification performs one action; a queue message for another AWS account produces no public state change. Verify pause after expired temporary credentials, reauthorization on the same account, and replay after old channel removal.

## Other AWS deployments

Existing MediaLive → MediaPackage → CloudFront deployments can supply an authorized HLS/DASH playback URL and optional protected export location. Accept the outputs the church identifies. CloudFront is a distributor and S3 is object storage. Lightsail identifies a host; discover its actual software/protocol. A MediaLive scheduled input switch changes production and may incur charges; it is independent of a congregation's calendar. Support read-only existing outputs by default and represent any approved playout automation as a distinct, explicitly enabled action. AWS IVS Real-Time stages have a separate participant SDK and permissions: request a church-provided compatible broadcast output or external destination unless a dedicated Real-Time adapter is separately specified.
