# From live broadcast to an attributed sermon

## Let the church choose

Four decisions are independent. Capture chooses where a recording is made. Backup chooses what is retained locally. Playback chooses which verified copy the congregation receives. Publication chooses when it appears. Show these choices before the first service, with disk estimates, permissions, provider charges/limits and writing actions spelled out.

| Recording choice | Worker action | Sermon and playback |
| --- | --- | --- |
| Live only | Disable optional recording where the provider supports it. Disclose automatic provider recording where mandatory. Never promise “never recorded” on an automatically archiving provider. | No automatic empty sermon. Existing manually linked sermons are untouched. |
| Provider archive only | Wait for authorized VOD completion and store durable playback identity and provenance. | Create or link a sermon if the church enables automatic archiving. Play from provider via native/approved embed mode. |
| Provider plus local copy | Obtain authorized video and/or audio export for the specific asset. Download and verify each requested track. | One sermon for all tracks. Church selects preferred local or provider replay and permitted fallback. |
| Local canonical archive | Import church-owned original, supported provider export, or explicit authorized capture. Preserve caption tracks when available. | Publish from the verified church storage. Remote cleanup is separately opted into and executed only after verification and reference checks. |
| Operator's encoder file | Select the occurrence and upload the OBS camera/master file through existing Files workflow. Allow resumable staging when supported | Enables local replays for YouTube, Telegram, Zoom or any link-only venue. Match explicit occurrence, independent of the social platform. |
| Authorized server-side capture | Optional recorder pulls the church's own permitted media source or consumes an explicitly supplied feed with capture rights. A supervised worker and storage are required. | Creates a recording locally. The shared-hosting baseline continues to work without such a worker. Never treat this as permission to copy a protected platform stream. |
| Browser capture | Optional operator workflow for their **own** camera/microphone or explicit source with user permission. Offer local save/upload and integrity confirmation. | Closing the tab, lost permission, unsupported codecs or interrupted upload can lose the capture. A spectator loading the public player never starts recording. |

The website player displays media. It cannot guarantee a server-side recording by playing a video, read cross-origin provider iframe media, bypass DRM or preserve a service after the tab closes. For an unattended church on ordinary Joomla hosting, use provider recording followed by a queued authorized export. If the provider has no export, show the encoder-file workflow at setup. If only video is provided and the church wants audio, derive audio from the authorized local master on a capable worker, or accept a separate audio upload. Browser microphone and archive extraction are different operations.

## Transfer protocol

1. Reserve a unique intent for occurrence + source asset + rendition. Record the chosen policy snapshot. Confirm church ownership, access, rights, output quota, file-type configuration and recording completeness. Keep the source identity even when download URLs expire.
2. Ask the provider for the authorized finished rendition or temporary master URL, using server-side credentials. Wait for the provider's export-ready signal or poll its explicit status. Video playable rarely means downloadable MP4 already exists. For HLS object archives verify final recording metadata/end marker and the scope of all referenced media.
3. Stream to a private temporary object/path under a generated filename. Use bounded chunks and a byte ceiling independent of Content-Length. Check redirects, allowed origins, MIME/signature, disk space, elapsed time, size and ownership. Avoid placing full movies into PHP memory or database blobs.
4. Persist transfer checkpoints. Resume only with proven byte-range support and matching remote identity, size and validator/version. If the origin changes or resumed response returns the full object, discard partial data and restart safely. Refresh expired URLs using asset identity, never persist them as permanent playback URLs.
5. Verify successful completion: expected length when available, readable container, intended audio/video tracks, nonzero duration when supplied, checksum of completed local bytes, and sample playback/seek. An HTTP 200 HTML login page or a playlist with missing segments fails verification. For multivariant HLS keep a consistent local manifest tree and relative references or create a separate verified MP4 using an authorized job. A local checksum alone cannot establish source completeness.
6. Promote to final storage atomically on the same filesystem, or commit a completed object and switch a versioned pointer. Record local file GUID, content digest, size, media duration and provenance. Register through the existing Files rules and service identity. On rename-before-database failure discover the reserved file and finish the link. On database-before-availability failure mark unavailable and retry.
7. Permit the church to require local verification before public sermon publication. Keep the provider replay available only under its own access policy. Send the editor a useful failure or completion summary. Deleting upstream is a separate explicit setting and permission, never a side effect of selecting “Play locally”.

## Automatically create or update the sermon

Snapshot host church, actual preacher, title, event date/time and timezone, intended access/publication, optional series/category, and contributor identity. On the first eligible archive event reserve the sermon association. If an editor already linked a valid sermon for this occurrence, use it. Otherwise use the actual Sermon model to save the agreed values and row GUID. Apply validation, access asset creation and version/language semantics. In the inspected public model an API create generates its own GUID. If using that entry point, record the returned server-owned identity and ensure the durable correlation marker is committed with the native save. Never depend on an API accepting a caller-selected sermon GUID. Keep unpublished/draft as the initial default. Allow explicitly authorized auto-publication for complete mapped services.

| Value | Source precedence and conflict behavior |
| --- | --- |
| Church | Occurrence host → approved manual correction. Verify row exists and operator can use it. Never infer from provider profile or the preacher's home church. |
| Preacher | Confirmed occurrence override → programme default fixed at occurrence generation. Missing, removed or ambiguous speaker opens an editorial task. Stage the media without publishing a guessed attribution. |
| Title and service date | Occurrence metadata. Reconcile provider title only for imported/provider-owned fields. Keep recording time distinct from date preached and upload date. Do not overwrite editor changes. |
| Series/category | Occurrence override → programme defaults → absent if allowed. A deleted relation prompts remap according to field requirements. |
| Media | Video and audio variants, backup sources, captions and authorized external replay all relate to the same occurrence. Verified local attachments use the existing sermon entity target. An audio arrival after video adds a variant. It never creates another sermon. |
| Access and language | Use church policy plus occurrence/sermon view levels. If effective access cannot be expressed by a single field, enforce the intersection at delivery. Hold publication while ambiguous. |
| Publication | Check required credentials, source readiness, metadata completeness and publish authority. Optional review is a first-class workflow. A metadata retry cannot republish an intentionally unpublished sermon. |

Multiple fragments from a lost encoder remain one service if confirmed by session/reconnect identity. Use an ordered part list. Do not silently splice gaps or truncate the recording. If one input captured two consecutive services, let an editor mark boundaries or submit separate originals before attaching media. Distinct simulcast platform replays are alternate sources for the same sermon. Choose a canonical one. For several talks within a service, allow an editor to link/split additional sermons explicitly while keeping exactly one automatic primary association. A previously generated sermon with local edits is never recreated just because the account disconnected.

## Capacity and lifecycle

At 3 Mbps total, a 90-minute recording is approximately 2.025 GB decimal. At 96 kbps, 90-minute audio is approximately 64.8 MB. Multiply by variants, retained weeks and concurrent partial copies. Reserve temporary headroom for conversion and a backup. Warn before enabling a policy that exceeds hosting quota. A slow shared host may need several task runs for one export. Prioritize imminent service control and webhook receipt ahead of large transfer jobs.

A verified copy on the same physical server protects against provider deletion but is not a disaster recovery backup for that server. Include both Joomla database and private media in the church's normal backup. Restore to another site, remap file roots and verify a sample with credentials disconnected. Preserve remote masters until the selected local retention policy has been satisfied. A cancelled or privacy-restricted event must never leak via a guessed filename or alternate public replay.
