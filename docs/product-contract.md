# Church-owned live streaming

A church installs Sermon Distributor on its Joomla site, connects its own provider account, and keeps control of broadcasting, access and retention. Offer Mux first. Connecting an existing setup is an equally supported entry point. The church can keep its encoder settings when it adopts an existing destination.

The congregation should have a stable church URL for a service, a working way to watch or listen, and an accurate account of whether the preacher is live. Editors should schedule once, select a preacher and church once, and receive one correctly attributed sermon when permitted recordings become available.

Deliver the future feature through the supplied JCB blueprint. These documents describe decisions and verification for that future work. They do not provision accounts, install a media server, change the component or require a subscription to a Sermon Distributor intermediary.

## Decisions owned by the church

| Decision | Choices |
| --- | --- |
| Broadcast provider | Church-owned managed account, existing broadcast endpoint, supported third-party player, or external destination |
| Site playback | Church player for authorized media, approved provider player, or a clearly identified external action |
| Recording | Provider recording, authorized local capture or original-file import, or live only |
| Replay | Provider playback, verified local audio or video, or both with an explicit preference |
| Publication | Existing sermon workflow and access rules, with automatic publication available only when explicitly configured |
| Calendar | Author in Joomla and synchronize supported provider events, or adopt the church's existing provider schedule |

The implementation handoff must distinguish published provider capabilities from account entitlements and from facts that only the supplied blueprint can establish.
