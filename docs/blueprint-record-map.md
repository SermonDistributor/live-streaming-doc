# Record-by-record JCB authoring map

Use this alongside the [package intake](blueprint-handoff.md) and [logical records](data-contract.md). The record labels below are proposed responsibilities. Select actual aliases and definition IDs in the supplied package. Preserve existing public routes and GUID fields. The generated output provides evidence about behavior, while the supplied package owns changes.

## What to inspect in the existing component

| Feature | Reference input/hook to trace | Consequence during implementation |
| --- | --- | --- |
| Server-generated sermon identity | The public SermonModel::save normalizes the local integer id, retains an existing stored GUID, and clears a caller-supplied GUID on an API create before generating a valid unique GUID | A webhook cannot send an occurrence GUID to the Joomla public create API and assume this becomes the sermon GUID. Reserve the occurrence, save under a trusted native model transaction/creation marker and persist the actual returned row identity. Keep tags/languages untouched on partial updates. |
| Save lifecycle | Sermon model and table handle alias, created/modified, ordering and Joomla asset behavior | Invoke the normal save/validation path under a scoped service identity. Bind the actual church/preacher and access fields. Read back the saved row, alias, asset and GUID. Avoid direct inserts that skip component logic. |
| Managed file target | The public sermon form's entityfiletypes control uses entity=sermon. The displayed uploader and file display are Note fields | Reuse the sermon target and configured media file types. Notes and selectors drive the UI rather than storing file bytes. Inspect real download/stream access in both admin and site consumers of the supplied version. |
| File limit effects | File.Manager's file limit compares entity, entity_type and file_type before selecting excess records | Verify policy with an existing master and a new derivative. Export retries cannot trigger quota-based replacement of unrelated files. Use separate allowed types or explicit replacement review where necessary. |
| Source/view contract divergence | Site samples have download_links, playerKey and computed preacher/series/category links, while the inspected public install schema has its own columns | Preserve the active package's source/link selection conventions. Do not reassign enum values from a sample or equate a generated download link with a permanent media URL. |
| Church/preacher relations | Existing modal selectors resolve #__sermondistributor_church.guid and #__sermondistributor_preacher.guid | Extend the church/preacher selectors or add view filters under native hooks. Do not duplicate Churches and Preachers or rely on cross-site numeric IDs. |

## Provider operation boundary

Prefer the smallest JCB-native callers. A generic destination can return static validated player/URL descriptors. It needs no stub OAuth client or false “success” methods. Providers implement only their advertised operations, e.g. discover/adopt resources, fetch broadcast state, read/write a scheduled event, resolve playback and acquire an entitled archive. Keep scheduling, start/stop, recording export and remote deletion independently permissioned. Invoke the capability test before presenting or dispatching each action.

The task entry point passes church-bound connection, target resource, desired revision and correlation identity. It returns verified provider state or a structured outcome: pending, ready, unsupported, requires permission, quota delay, conflict, transient failure or permanent rejection. Include retry timing and public-safe diagnostic code, keeping raw private evidence within the protected operator context. Callers use those outcomes consistently in dashboard, worker and public status.

## Public query acceptance

For anonymous Preacher A with a future service, fetch the current preacher by its existing route. Add zero live entries and the next visible occurrence. On authenticated active signal return its occurrence GUID, church label, public status, start and routed link. Countdowns query occurrences independently of multi-source archive tables. For a signed player, return the stable authorized local playback action. Mint short-lived provider tokens in a separately authorized request. If a published event has one private and one public destination, list the event exactly once and only surface the allowable destination(s).
